# 生产与视觉验证

先在实际设计参考上确定每个元素的原像素框、设计坐标框和最终PNG尺寸，再提取或独立生成。默认1920×1080设计尺寸，参考图像素不同时按四边映射，不直接把模型原尺寸当设计尺寸。PNG整体边界（含透明留白）和设计框宽高一致，可见内容在1:1组合中核对；不得擅自放大主体、加大透明边或借CSS/FGUI缩放掩盖错误。新正式资产启用native_size_required，运行`art_tool.py handoff`；未匹配的图只保留待处理状态，不能交付为正式素材。

浏览入口优先加载独立缩略图；大原件不得仅靠CSS缩小冒充缩略图。每图下方显示名称、资源文件名、原图像素/体积、缩略图像素/体积，原件可点击打开。库级预览按[资源契约](resources.md)生成与检查；原尺寸检查视图仍使用原图。制作设计尺寸与匹配状态单列，不能由缩略尺寸替代。

效果图用于方向、层级与风格参考，不作为可直接裁切的默认素材源。先实际读图，再写 analysis.md：画面用途、观察到的元素、重复轮廓/材质、遮挡、分层清单与复用决定。

默认先建立 1920×1080 设计基准，明确每项独立 PNG 的目标宽高与画面占用位置。例如主体 PNG 256×256、公共底座 PNG 320×320（其中透明留白与可见轮廓占用不同）；具体尺寸按实际设计而非统一套数值。图像模型原始输出大小、正式 PNG 原大小、效果图中使用大小分别记录。背景不参与默认效果图。

逐项提示词：用途 → 固定风格片段 → 单一主体 → 构图与接触面 → 保留特征 → 禁止项。每次保存工具实际收到的完整提示词，不只保存摘要。每项单独调用内置 imagegen；参考图先查看，工具参数依当前工具文档填写，不能虚构尺寸或保存路径参数。

底座与主体必须可独立使用：底座不带入口主体，主体不带牌匾或岛屿；背景不含 UI、文字和前景入口。透明层保留柔边、抗锯齿和有效半透明光效，不能把棋盘格当透明。图像处理遵循当前工具规则，不以程序生成或改图代替要求的生图。归档工具仅复制和检查图片。

检查两部分：工具只读检查文件、尺寸和 alpha；人工查看轮廓完整、无邻接元素、无字、分层正确、材质和光照一致。alpha 存在不证明透明区域正确；结构检查不证明视觉合格。描述检查限制，实际不合格的素材不登记为通过。

之后执行 [主体与底座协调检查](pairing.md)：实际素材组合与方向效果图分别查看。精度不足、漂浮、视角冲突或重复底框时，必须修正搭配或重绘美术，再回到组合检查；不为了复用而将明显不协调的主体判为通过。

美术搭配预览可用 HTML 的图片层显示真实文件，不生成 UI 控件或交互。UI 素材默认使用中性底色，不叠加场景背景；背景若存在放独立展示区。预览缩放仅是显示比例，不改变 PNG 原尺寸。必须同时交付原尺寸元数据，避免其它技能误认为图片已满足项目的固定规格。

每项素材正下方必须有文字标注：可读名称、原尺寸、设计目标尺寸、匹配状态；名称和说明由预览的文字层显示，不烘焙进 PNG。设计画布内按设计像素放置，原尺寸检查视图按 PNG 实测大小显示，较大图片使用滚动查看而非偷偷缩小。网页整体查看缩放须单独标明，不把显示缩放称为素材原大小。

参考示例：先生成效果图；再生成公共底座；缺失主体分别生成；新增主体引用同一底座，以证明可复用。失败重试针对具体项，持续失败则交付未完成清单，不无限生成。
