# 模块优先文档布局验证

本次改为 docs/文档/<模块>/，模块内部组织 README、同级目录架构、职责、原语言 API 和需要的专题。根与模块 README 都有类导航，根同时导航模块。设计稿保存在模块的设计任务目录，不混入当前实现。规划工单链接实际模块入口、类文档、目录架构和 API。

## 真实检查

- 总目录及三个单模块检查通过；旧顶层职责/API结构被 MODULE_LAYOUT 拒绝，缺模块 README/目录架构被 MODULE_ENTRY 拒绝，入口不链接同级目录架构被 DIRECTORY_MAP_LINK 拒绝。共 8 个正反例。
- 模块内设计态文档及 planned API 用 planning 模式检查通过；正式目录扫描跳过保存的设计稿，只检查当前实现。两个模式共 2 次通过。
- 六份类说明除相对路径、跳转与更新时间外全部内容一致，生命周期、持有边界、流水线用途与契约说明没有丢失；四份 API 原语言声明迁移前后字节一致。
- 六份原工单导航到对应模块后检查通过，本轮仍为待执行状态，不把导航检查写成工单验收通过。
- 现有正式样例检查 27 文件通过；两个技能 quick_validate 通过。本地文档及流程图目标迁移后已检查。

## 独立生成试用

独立无历史上下文代理从只读源码和旧 API 重新生成三个模块目录，9 个类型/9 份原语言声明。逐类型签名比较共 37 方法与提供源码匹配，原始 23 方法全部保留，并从源码补录了 14 方法；仅对提供源码范围保证，不宣称覆盖完整工程。

正式检查 35 个文件（26 Markdown、9 API 声明）零问题。独立核对 148 个本地 Markdown/Mermaid 引用和锚点，全部有效；检查有效帧顺序、跨调度信号及持有/释放限制。已在输出 docs 建立独立本地 Git，确认父输出目录不是 Git，未配置远程、暂存、提交或推送；临时脚本/报告在 docs 仓库外。

生成过程中首次出现 API 节混入导航、缺位置树表、自文档锚点格式的问题，代理按工具反馈修正后通过；不声称第一遍就全部正确。未运行完整构建、动态玩法或完整图渲染；缺少事件基类/注册表/端口完整实现，契约核对仅限提供源码。

## 范围

所有试验、缺陷注入与临时脚本在仓库外隔离目录。只迁移技能仓库的样例，未迁移或修改生产项目 docs、SDK 缓存、源代码；未验证真实游戏运行或完整编译。结构工具不能证明业务事实，系统内容仍需对照相关源码核对。
