# 独立子代理试用

使用不携带父对话历史的子代理，只提供两项工作版技能、六份原始源码和四份现有 API 快照。代理自行完成已实现补录和同结构设计态任务，没有阅读本目录样例或预期答案，未修改生产项目/技能。

## 实际产物与检查

- 两态各生成 22 个类型职责文档、10 份代码 API、38 条公开方法声明。
- 当前统一规划入口调用文档生成器，两态均包含目录/脚本位置、角色、调度流水线和唯一 TODO；正式目录不复制测试结果。
- 所有生成目录均有 README；最终额外核对 411 处路径/锚点无缺失，技能检查通过。
- 两个隔离输出的 docs 分别建立本地独立 Git；无暂存、提交、远程或推送。
- 首次发现 Windows 子进程默认编码错误。实现改为内部固定 UTF-8 后，移除外部编码变量和强制 GBK 环境下，两模式/两工具共 8 次复验全部通过。
- API 节只保留声明链接，README 导航另放章节，与代码 API 的规则一致。

## 局限

没有完整工程/SDK/外围实现，未进行语义编译、游戏运行及独立产物 Mermaid 渲染；结构与引用通过不证明完整业务正确。主代理只另行渲染了两技能的三个操作图，约 20px。

原始独立报告、两态完整产物和临时试用脚本保存在仓库外实验目录，不将测试代码加入技能。[本仓库示例核对](review.md) 记录生成器/TODO 所有权和目录约束检查。
