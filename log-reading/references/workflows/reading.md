# 日志读取与关联

## 读取顺序
1. 对目标会话确认开始/结束、项目、端和版本/模式（日志实际存在时）；同时查相关轮转片段。保留复现时间窗口。
2. 搜索用户症状、模块/请求标识和异常类型，再查 error/warn/fatal；错误词不是唯一入口。业务失败可能只有普通级别事件。
3. 展开命中前后上下文及完整堆栈，保留 InnerException、Caused by、异步 await 边界和目标调用参数的必要含义。若截断，从相邻片段恢复；找不到则写截断。
4. 从最早与本次行为有关的失败整理事件链；后续重试、取消、连接关闭、资源失败和 timeout 区分连带症状。跨线程输出的打印顺序不必是执行顺序。

PowerShell 的 Select-String 可显示路径和行号；rg 支持快速上下文：
~~~powershell
rg -n -F -C 8 -- $m_keyword $m_logFile
Select-String -LiteralPath $m_logFile -SimpleMatch -Pattern $m_keyword -Context 8,12
~~~
使用已确认文件，正确保留空格/中文路径。UTF-8 文件正常时使用显式 UTF8；Windows PowerShell 5.1 乱码先确认 pwsh 可用性与实际源编码，不修改原日志“修乱码”。二进制或特有格式用项目已有 reader，不用文本命令猜解码。JSON/NDJSON 保留记录边界并按真实字段筛选，多行异常不能把每行当独立事件。

## 跨文件与双端
优先 SessionId/RunId、RequestId、玩家/客户端槽位、目标资源和进程 ID 等实际已有标识，不编造不存在的字段。请求 ID 可能重用，必须结合会话。多客户端按槽位/玩家/实例区分，不能混读不同视口。

时间带时区时转换为同一基准再比较，保留原时间；没有时区或存在时钟偏差则标注，按协议/请求关系辅助排序，不把毫秒先后当确定因果。轮转分片按事件时间和会话关联，不只按文件名排序。

客户端 timeout 与服务端异常同时存在时，先核对同一请求是否送达/被拒绝；不能未经证据直接归咎网络或 UI。服务端 Ready 不代表客户端 Ready，成功返回含义按真实 API 确认。需要源码/API 定位时只查堆栈/相关模块，不为读日志全量扫描。

持续跟踪仅在用户需要观察时使用，给有限窗口/终止条件；不要无限 tail。若用户授权复现，记录开始基准、结束边界及新增日志位置，不能把旧行再次当新故障。
