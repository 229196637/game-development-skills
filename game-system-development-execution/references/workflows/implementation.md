# 领取与实现

1. 核对用户授权范围与任务入口；阅读项目 AGENTS、文档根/模块 README 和任务 README。运行规划工具 check、执行工具 next；缺 TODO 用规划 order 生成，先处理坏链接、缺文档及循环依赖。
2. `claim` 按入口 TODO 选择首个前置已完成的 todo，记录领取人和时间并改 doing，返回具体工单与文档索引。领取前不得写本次业务代码。已被领取的任务通过 show 恢复；不要抢占其他执行者。
3. 读取工单目标、当前改动、工作项、验收标准；沿索引读对应类 MD、模块 README、目录架构、原语言 API 及适用网络/UI/配置专题。已有 API 资料可用则先读 API，不重复扫描完整代码；实现时仍查相关真实源文件。复用已有框架；接口冲突或需要重写但尚未决策时说明细节并请求业务决定。
4. 按文档脚本路径和公开契约实现，执行者负责行为，调度者按各流水线和跨系统通信设计实现，工具/数据遵循既定角色。逐项验证完成后 set-item done；不要把勾选当成测试通过。
5. 若实际实现必须改变设计，调用文档技能同步，必要时交规划 update 修订工单。doing 工单须先 release；update 会保留历史但使本轮旧结果失效，再按 TODO 重新领取。不可执行过程中悄悄改验收条件绕过失败。
6. 转 [测试与交付](verification.md)。环境/业务缺口无法继续就 block，写具体原因与恢复条件；脚本可继续返回不依赖此任务的可执行项。全部阻塞时交付缺口，不虚报完成。

入口 TODO 是稳定优先顺序，状态只存类工单；跨系统运行时通信不一定是开发前置，遵守规划定义的依赖。多个执行者可领取不同的就绪工单，但不能跨越未完成前置；锁只防工具操作冲突，不替代源码并行修改协调。
