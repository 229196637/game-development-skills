# 职责架构与系统依赖图

凡 README 包含“类索引”，同时提供“## 职责架构图”和“## 系统依赖图”，正式总入口、模块入口与设计入口均适用。普通职责/API 子目录摘要不重复全量图；规划工单 README 仍只维护 TODO，不复制文档架构。

职责架构图：节点名称与类索引、类文件名一致，标角色和简短职责；用已核实的边区分调用、持有/借用、产出数据与协作。覆盖本入口索引的类，每个类节点 click 到它的职责 MD，图下给相同 Markdown 链接。独立类保留独立节点，不为连成图虚构调用。

系统依赖图：从相关类/系统 meta 的文档依赖及实际契约提炼，标明“消费者 → 提供者”，边上概括用途；纯资料查阅标“文档引用”，不冒充代码调用。跨模块节点直达对方 README 或具体类 MD；模块入口仅展开本模块及直接上下游，总入口画跨系统总览。依赖信息仍以所属文档 meta 为准，入口图只可视化，不维护第二份依赖表。设计态图明确“设计/未实现”，不能冒充当前代码。

无已确认外部依赖时保留本模块节点并写明“无已确认外部依赖”，不省略系统依赖图，也不把依赖图画成 TODO 执行顺序。详细持有/释放、生命周期和每条调度流水线留在类 MD，不堆进入口。

图前用一句话说明用途；默认 20px 字体，图过宽按模块拆分并链接局部图，不缩成不可读的长图。类新增/删除/改名、角色或依赖变化时，同步类索引、两图、meta 和跳转；改后检查 Mermaid 渲染及节点链接。
