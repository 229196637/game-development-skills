# 增量同步
先定位本次实现差异与受影响系统，不覆盖用户已有改动。没有文档时专项补录；有规划时只用它核对已确认目标与差异，不复制成正式文档。

## 必须同步
- 调度器：按 [调度器与执行者](dispatchers.md) 同步设计模式 meta、每条实际流水线图、跨调度器通信与跳转；执行者只说明执行内容。
- 架构图与职责：更新真实模块/类、端归属、依赖方向及状态 owner。
- 持有关系：谁创建、谁持有、拥有还是借用、谁释放；同步资源和订阅/回调清理。
- 生命周期：初始化前置、进入/运行/暂停的实际能力、关闭/释放顺序与真实取消/错误边界。用简短说明，不强制新增流程/时序/状态图。
- 依赖 meta：只更新 dependencies 的实际系统文档及 uses；不要另复制依赖表或版本列表。
- API：按本次变更核对实际公开函数签名/契约、来源与头部版本/日期。完善同一份 planned/mixed 文件，全部实现核对后移交正式位置并更新引用，避免重复声明。
- UI/Excel/网络：需要时更新独立专题及 HTML/字段注释/协议事件；主体保留入口与必要约束，不复制整套规划、字典或测试矩阵。
- 正文与 meta：按 [SDK 式系统说明](../contracts/document-layout.md#sdk-式系统说明) 整理用途、接入/调用的短示例和生命周期；实现变更同步影响到的示例与操作限制，不追加一段修改流水。日期/基线/来源与核对范围一致。无用模板章节直接删除。

已有任务的 TODO、测试/验收状态与证据仍在任务入口或专项报告更新，正式系统主体不复制。规划仍可有详细流程和时序图，不能反向用其模板约束正式文档。

## 验证与交付
检查架构、owner、生命周期与实现一致，借用对象无错误释放描述；精简 meta 可解析、dependencies/API/UI/配置专题链接有效，源码来源和代码基线真实。有工具时检查架构图可读；未渲染只标源码检查。

运行与实现变化有关的项目验证；纯技能/文档改动不运行无关游戏测试。系统正文不写验证或测试说明，全部测试内容与执行记录放任务测试文件/独立报告。已实现行为限制仍保留在生命周期和使用契约中。交付区分修改内容、真实验证和未完成项，分别检查代码与 docs Git；不把未验证部分称为通过。
