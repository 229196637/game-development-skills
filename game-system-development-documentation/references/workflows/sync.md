# 增量同步
## 定位
先检查当前差异和任务范围，记录涉及系统、公开 API 的消费者、事件与配置依赖。不要覆盖用户已有未提交文档。没有系统文档时对该系统专项扫描补录，不强制全工程扫描。

## 同步内容
- 架构：源文件变化、类职责、依赖方向、初始化/释放、权威和端归属；同步每模块依赖架构图、节点/接口映射及图例。
- 流程：同步各模块关键流程图和必要的时序/状态图，核对实际接口、状态所有权、消息顺序与真实分支，并修订对应验收场景。
- 契约：新增/删除/改签名的 API、空值、真实校验和异常、调用顺序、状态与事件、取消/线程约束。
- 配置：涉及 Excel 时同步字段字典及每字段注释，核对 Excel TIPS/说明列与生成配置原生注释的用途、单位、格式、默认/特殊值和外键语义一致；同步表头/类型/空值/端开关、外键、输出类型与路径、转换及读取映射，记录实际导出/一致性检查和读表结果，不直接把字段加入公开函数 API。
- UI：涉及时同步独立 UI 说明及可直接打开的 HTML 设计稿，核对业务执行端与 View/模块根目录归属，更新布局、状态/交互、接口/事件/网络刷新、资源发布、实际生命周期和验收；长期系统主体与任务入口保持可跳转，无 UI 不补空稿。
- 使用：真实示例、迁移步骤、与优化有关的约束。删除或修改过时示例和链接。
- API：逐函数核实 planned/mixed/implemented，完善规划阶段的同一套 API 文件，不另建重复声明；文件内函数全部实现核对后移动到正式 API 端/模块目录，planned/mixed 文件继续留在任务中，迁移时同步所有链接及版本并避免覆盖无关成员；根据此次实现差异重新核对原语言公开函数声明，同步签名及契约注释、文件头的真实代码版本/源码/日期/验证状态和系统 Markdown 映射；纯内部优化且签名不变时仍检查行为说明。
- 规划：存在规划则同步总规划 TODO、依赖/接口关系、开发/测试/验收状态和证据，以及实际完成状态和偏离原因；不存在则不用补造。
- meta：更新日期、来源、基线、验证范围、相关文档；被间接影响的系统也更新。

## 验证与交付
核对签名和正文是否一致，参数可空、返回 null 含义和异常是否真实；检查 meta 能解析、所有本地文档链接与索引存在；逐模块核对依赖架构图及关键流程图齐全且与实现一致。有图渲染工具时按实际文档宽度检查字体、密度和分支标签可读性；超宽图优先纵向/按端或阶段拆分且保留全部关系，不只放大源字体。没有渲染工具时明确只做图源码检查。API 文档应覆盖清单内实际对外公开的函数/方法，保留必要类型归属；不收录字段、属性或非公开函数，特殊端或接口需说明。
运行与生产变更相关的项目验证，并记录结果。仅改文档时不为了仪式运行无关业务测试；改变编译项则运行强制构建。
当前开发任务从 docs/规划/<任务>/index.md 进入，任务详情和各模块规划保存在该任务文件夹内；从任务入口链接长期系统说明与 API 映射，不在 API 文件夹创建额外入口。整体任务验收需覆盖受影响系统的集成流程；implemented 不表示测试通过，未实际验证不能标 verified/accepted，人工验收只有用户要求时保留待确认。
交付前分别查看两仓库 diff 和 status，说明代码与文档版本是否已提交以及剩余事项。同步未完成应明确报告，不将开发任务宣称完全完成。
