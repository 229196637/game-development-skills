# 老工程补录
1. 先查已有系统说明与 API；确需扫描时定位实际模块入口、注册、实现和消费边界，避免全工程无差别扫描。
2. 从创建/注册到释放追踪真实状态 owner、对象 owner 与借用关系、关键依赖和回调；公开契约、取消/失败分支以实际实现为准。
3. 使用 [精简文档协议](../contracts/document-layout.md) 提炼一份系统主体和实际架构图；生命周期写简短顺序，持有/释放写准确表格。系统依赖及用途只在 meta.dependencies 维护。
4. 输出原语言公开函数 API 并在主体直接映射；不复制函数注释、规划内容、完整目录清单或生成文件清单。不补造历史规划。
5. 更新必要索引，核对精简 meta、依赖/API/专题跳转与构建隔离。静态阅读与动态验证分开，一段交代实际核对范围和已知缺口即可。

仅有部分模块证据时不声称全项目覆盖。正文中不保留扫描过程、全量覆盖统计或反复构建历史；用户要求专项扫描报告时单独交付。
