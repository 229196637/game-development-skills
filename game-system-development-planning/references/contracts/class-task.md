# 逐类任务记录

每类一份开发工单，参照 [类任务模板](../../assets/templates/class-task.md)。meta 使用 JSON 值的 YAML，工具用标准库读取。字段为 task_id、class、document、status、depends_on、required_tests、required_acceptance、updated；前置与测试/验收 ID 稳定，updated 包含时分秒和时区。状态 todo/doing/blocked/completed。

正文依次如下：

1. **目标**：本次要交付什么结果。
2. **当前情况与改动**：当前有哪些文件/行为，哪些缺失或不符合要求；本次新增/修改/删除什么，改动范围和重要约束。写实际工作说明，不复制完整设计，不用“待完善”占位。
3. **文档索引**：对应类 MD、文档 README、与其同级的目录架构 MD，以及相关原语言 API、网络/UI/配置专题。每项链接直接可用。
4. **任务内容**：具体勾选项，说明真实文件/方法、操作、约束和交付结果。多个步骤按依赖排列。内容不应只是一项笼统“实现这个类”。
5. **验收标准**：表格 `验收 ID | 通过条件`，提前写可观察的通过条件，与 meta.required_acceptance 一一对应。测试方式/场景与真实项目适配；只涉及静态改动可用适当检查，不擅自加人工审批。
6. **测试过程**：`时间 | 测试 ID | 命令/步骤 | 预期 | 实际 | 结果 | 证据`，执行后追加。
7. **验收情况**：`时间 | 验收 ID | 实际情况 | 结果 | 证据`，执行后逐项追加；这是最后一节。

规划时前五节必须有实质内容；底部两表尚未执行可以没有结果，明确尚未执行，不能预填 passed。结果 passed/failed/not-run；每个 ID 以最近记录判定，保留失败历史。文档索引、测试日志和验收证据不能互相替代。完成门槛同时检查前置完成、勾选项、必需测试和验收最近全部通过，工具不证明记录的真实性。

旧七字段任务可用 update 填充完整工单；新增 required_acceptance，不另造 manifest。更新计划保留历史记录并退回 todo，旧通过结果标失效，新一轮重新执行和验收。
