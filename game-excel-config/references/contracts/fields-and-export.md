# 字段与导出规范
有 Excel 配置需求的模块，规划阶段在 docs/规划/<任务>/<模块>/config.md 保存字段与导出契约；开发后将实际配置说明整合到系统 Markdown 或其直接链接的配置专题。不要只写“数据放 Excel”，也不为此增加 API 清单文件。

## 表清单与工作簿布局
记录源工作簿相对路径、格式、Sheet、用途、行粒度、主键、真实表头/标签顺序、数据起始位置和有效行判断。新格式写拟定，现有格式按导出器核对。说明哪部分是说明/类型/开关，哪些单元格实际导出。
记录格式化与导出工具、已核对的参数、依赖、输入范围、生成路径、构建/资源注册及运行时读取入口；没有工具的规划注明工具待实现，不冒充已有链路。

## 字段字典
每一实际/拟定字段都填写下表，不仅记录名称：
| Sheet/字段（KEY） | 业务含义与单位 | Excel TYPE/填写格式 | 目标类型 | 必填/空单元格/默认值 | 取值约束 | 主键/外键及目标 | client | server | 字段注释/TIPS |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
写清缺省是导出器自动填值、业务默认还是不允许缺省，不能混用；0、空字符串、空数组、未填和 null 分开说明。数组、枚举、资源引用、表达式的存储格式必须能被实际导出器解析。
字段改名、类型变化、删字段记录对旧数据和调用方的影响。说明主键稳定性；外键缺失和可选值的含义依据业务确认。

## 字段注释必须完整
每个实际或拟定字段都必须有非空说明，不能只重复字段名、类型或写“编号/数值”。规划 config.md 保存“字段注释/TIPS”正文；源 Excel 使用项目既有说明行（如 TIPS）或说明列，策划无需查源码就能理解如何填写。
注释按字段实际语义说明：
- 字段用途、使用方以及单位/倍率，例如秒或毫秒、百分数或归一化比例，不能只写“冷却时间”。
- 必填与否、空单元格实际导出值、0/负数/空字符串等特殊值的具体含义；没有特殊含义不编造。
- 有效范围、枚举值含义、数组元素及排列顺序、表达式/资源引用的填写格式；仅声明已确认的约束。
- 主键稳定性；外键的目标工作簿/Sheet/KEY、可选引用及目标缺失时的已确认行为。
- 端侧差异和必要的调用限制；字段语义未确认写待确认，不假定业务。
生成源码配置时将字段说明同步为目标语言原生注释（C# XML、TS/JSDoc 等），保留语义并正确转义。JSON/二进制不强行插入非法注释，说明随关联字段字典/已有 schema 提供。没有注释透传能力的导出器明确记录缺口，并在获准修改导出器时补齐；不能手改生成文件伪装已支持。
每次字段新增、改名、类型/单位/缺省或引用变化，同步 config.md、Excel 说明、导出说明与系统用法。逐字段检查遗漏、中文截断、错误单位及不真实约束；重新导出后核对注释与实际转换行为，不以注释声称工具做了没有实现的校验。

## 源字段 → 导出结果
| 源工作簿/Sheet/KEY | 端侧开关 | 导出类型/字段及类型 | 输出路径/序列化格式 | 转换/缺省规则 | 读取函数及消费者 |
| --- | --- | --- | --- | --- | --- |
显示表级开关与字段级开关如何组合：某端整表关闭则该端不导出；整表启用时只有该端启用字段导出。字段双端启用表示两端输出，不一定物理生成到 shared；shared API 是共享读取契约，实际产物分布以工具为准。
说明导出产物是 C#/其他语言源码、JSON、二进制还是其他格式，以及何时加载、如何注册和查找。禁止把 source Sheet 名、生成类型名、注册表 ID 和读取 API 名混成一个概念。

## 生成和验收
列出查阅过的格式化 → 导出 → 一致性检查 → 必要构建/运行验证命令及预期结果。保留代码版本和工具来源；实际执行后将结果写入任务测试文件或独立报告，不进入正式系统/配置主体。
检查字段完整性、类型/范围、默认行为、数组/枚举编码、重复 Id/外键、端隔离、中文、生成注释及读表验证。外键规则或公式不一定已被工具校验，明确自动验证范围与手工补查项，不能声称全都自动校验。
字段属于配置数据说明，不因此加入只收录公开函数的 API 文档。公开读取函数仍放任务拟定 API，核对实现后由文档技能移至正式位置，并链接字段说明。
