# 流程
1. 先定位源表、字段格式、导出脚本及说明、生成目录、读取 API 和已有系统 Markdown；已有 API 足以回答时不扫描源码。若导出工具没有对应 API 文档，为操作它可定向阅读脚本入口与参数，不全工程扫描。
2. 设计阶段明确表用途、每行代表什么、字段类型与默认/空值、稳定 Id、外键、client/server/shared 使用方、业务权威和不应下发的字段。仅规划公开读取接口与依赖；未确认数值及规则写待确认。
3. 扩展既有表优先兼容已发布 Id 与字段语义。新增字段在表头/提示及读取契约同步说明，不随意改变生成格式或运行时接口。
4. 实际修改后运行当前项目已查阅的格式化、导出、生成一致性检查和必要测试。先查工具能处理什么，不能猜命令或复制个人技能来源项目的绝对路径。
5. 验证中文、字段类型、重复和非法 Id、外键、端导出、公式/引用、行列可读性与生成结果。改编译输入时按项目要求构建。
6. 系统 Markdown 记录源表相对路径、表关系、导出流程和实际验证；读取函数放各端模块的原语言 API 中，由 Markdown 映射。同步真实版本、状态与契约注释，不把拟定函数当成已实现。
没有导出工具的项目先定义格式与所需工具范围，只有用户授权创建导出器时才实现；技能本身不提供原项目专有生成器或依赖。
