# DSH 插件开发与 Git 管理

本仓库 [229196637/game-development-skills](https://github.com/229196637/game-development-skills) 保存我们实际开发的技能、DSH 插件和必要的官方插件补丁。只使用而未修改的第三方包按版本安装，不复制其整个 `node_modules`；开始修改第三方插件时，先明确源码归属、上游基线和更新方法。

## 已纳入的开发入口

| 类型 | 名称 | 本仓源码/入口 | 维护边界 |
| --- | --- | --- | --- |
| 自研插件 | 游戏开发工单 | [dsh-game-system-workorders](dsh-game-system-workorders/README.md) | 源码、测试、构建脚本、依赖锁进入 Git；发布包由源码构建 |
| 自研插件 | 本轮改动过滤 | [dsh-changes-filter](dsh-changes-filter/README.md) | 独立 DSH 插件；本地项目中的安装/开发副本不自动等于本仓最新源码 |
| 自研插件 | 规划/执行审查模型 | [dsh-plan-review-model](../plugins/dsh-plan-review-model/README.md) | 本仓保留源码；另有独立 [dsh-plan-review-model](https://github.com/229196637/dsh-plan-review-model) 仓库，后续变更须明确同步方向，不能认为两个工作副本自动一致 |
| 官方模块补丁 | 目标动作与图片草稿 | [dsh-host-patches](dsh-host-patches/README.md) | 维护变换源码、官方版本/指纹、回归和可重复生成工具；不是新的 Cordis 插件，不直接复制宿主包 |

该表是开发入口，不是个人运行配置清单。已安装、已声明依赖、已加载、已启用是不同状态，不从 `package.json` 推断插件一定正在运行。

## 后续开发约定

1. 开始改动前确定源码目录和上游来源。新增独立插件放 `tools/<插件名>/`，包含说明、源码、测试、元数据及必要锁文件；已有 `plugins/` 下的源码保持路径，不为了统一外观强搬历史。
2. 开发与安装分开：先在受管源码里改动、运行测试，再构建/打包或链接进 DSH。只有安装目录手改不算已纳入 Git；官方闭包内部修复无法经公开 API 实现时，进入 `dsh-host-patches` 的明确版本补丁边界。
3. 每次提交核对差异，只提交本次拥有的文件；不顺带提交别的会话未完成改动。运行任务时不强制重启当前 DSH；需要重启的安装由用户择时执行。
4. 提交源码、测试、文档、必要锁文件以及来源/版本记录；不提交个人 `.dsh` 配置、凭据、用户会话、原图草稿、完整依赖、缓存、应用二进制或备份。补丁生成目录应始终由 Git 忽略。
5. 第三方包在自己的上游或明确的 fork 中维护；卫星/独立仓保留历史，主仓只记版本/提交或经说明的源码同步，不静默改写远程地址或把第三方仓库当作我们的仓库。

现有工单插件及其他开发副本的未提交工作不因新增此约定自动入库。将某个额外插件迁入本仓时，单独核对其来源、许可证、版本差异和测试，不把个人安装现场整体上传。
