# DSH 游戏开发工单

原生 DSH Host/Client 插件：在会话内查看 game-system 技能的 Markdown 工单、按最近更新选择任务，在当前会话排队启动规划或执行。工单文件是唯一状态来源，插件不另建任务数据库，不修改工单或绕过领取/测试/验收门禁。

## 使用

- `/game-tickets`：独立只读扫描当前工作目录下的 `docs/规划`。在输入区的「查看工单」或会话「游戏工单」视图中查看，无须等待当前模型工作结束。
- `/game-execute`：打开未完成任务选择器，不会静默执行最新任务。输入该命令时，插件提供最近任务候选；可点选补全路径。也支持 `/game-execute "D:\\Project\\Example\\docs\\规划\\背包"`；命令的双引号路径采用 JSON 转义，界面会自动处理。
- `/game-plan 需要规划的功能需求`：向当前会话提交规划请求，只生成文档与工单，不自动执行。

界面按钮启动前会显示确认目标。忙碌会话使用原生 queue，不 steer、不新开模型会话。界面查询通过独立静态只读 Remote 直接完成，不进入模型队列，也不追加命令历史；显式 slash 命令仍保留原生命令记录。没有工单时显示空状态，不伪造演示任务。

## 界面

输入区只保留「打开工作台」按钮与当前任务名；完整界面在原生 `dialog`（top-layer）中打开。布局分四段：顶部标题条放任务名、根路径、任务选择器（目录、包含已完成、重扫、任务过滤）与四个统计胶囊（工单完成、工作项、阻塞、执行中）；中部左大右窄，左为可平移缩放的依赖画布，右上是所选工单详情（状态、领取者、前置、等待前置、进度与动作），右下是带状态 chips 与搜索的工单列表；底部整宽是所选工单的六个页签（工作项 / 测试 / 验收 / 证据 / 文档 / 规划）与原文视图。标题与统计固定，画布、右侧栏与详情带各自滚动，Esc/关闭后焦点回到原处。会话「游戏工单」视图复用同一组件。工单完成率与工作项完成率分开显示；工单完成不代表分支合并或任务级收尾已完成。

工作台使用局部不透明表面（`--gwo-surface` 由当前主题 `bg-layer-1` 归一透明度，运行时探针兜底），并标记 `data-we-surface-preserve`，避免壁纸/玻璃插件把面板文字与聊天背景叠在一起；不修改壁纸、玻璃或其他插件的全局样式与 composer 结构。

「证据」页只读解析工单最新测试报告与验收证据中的标准 Markdown 链接和图片：图片按需通过授权 Remote 读取字节生成缩略图（单项 5 MiB、整页 20 MiB、并发 3，Blob URL 及时释放），视频/音频/报告按钮经 `fileAddressFor` 交给已安装的原生侧栏预览（缺失时降级 better-sidebar）。Host 仅解析当前工单记录与一层 `.md` 报告中的链接，重新校验任务白名单、真实路径与符号链接；不支持任意路径读取、不拼内部媒体 URL、不自动播放或转码。打开侧栏前会先收起工作台但保留状态。

可见卡片每 15 秒刷新所选任务，隐藏页面暂停。后台文件变化时保留旧快照并提示不稳定，禁止用不稳定快照启动。切换任务、切换会话、关闭面板都会使在途查询与证据解析失效；后台会话的延迟结果不会在别的会话弹出面板。仅存储会话的所选任务路径偏好，不存任务状态。

「工单依赖图」是中部左卡里的可平移画布，默认展开：按前置关系自上而下分层，箭头从前置指向依赖它的工单，多前置、汇合与孤立工单都按真实关系画出。节点显示名称、ID、状态、可领取、下一就绪项与工作项进度；点节点即选中并同步右上详情与底部页签，若该状态被过滤则自动清除过滤，选中时高亮整条上下游并弱化无关节点。图基于完整快照，列表过滤不会删掉节点。右键在任意处（含卡片上）按下即可拖动平移，空白处左键也可拖动，中键不参与平移并抑制浏览器自动滚动；`Ctrl/⌘ + 滚轮` 以光标为锚缩放，普通滚轮上下平移；工具条另给 −、比例、+、适应、1:1 与定位当前。展开状态、平移与缩放按会话与任务根分别记住，收起不会丢失视野。键盘：画布聚焦后方向键平移（Shift 加速）、`+`/`-` 缩放、`0` 适应、`f` 定位当前；卡片间用方向键按空间最近邻移动，Escape 回到画布。画布自身滚动与裁剪，不会把工作台拉宽。超过 500 个工单或 2000 条依赖时默认只画所选工单的前后置闭包并提示规模，可切全图（硬顶 2000 节点 / 8000 边，超出如实提示截断）；缺失前置只按完整快照判定，局部图不会把界外前置误报成缺失。空任务、无依赖、循环（只标真实环成员，其后代单独标注为不可达）、缺失前置与重复 ID 都有提示，底层工单列表始终保留。

排布不是整齐网格：行仍按前置关系自上而下，但每行会朝其前置的平均位置偏移、层内卡片轻微错落；连线只朝目标方向倾斜——上下对齐的卡片走直线，不画回环的 S 形，跨层连线弯得更明显，所以同一张父卡对多张子卡会自然扇开。工具条可切回对齐的「分层」排布，两种选择按会话与任务根分别记住。正在执行（doing）的工单，其入边显示为沿依赖方向流动的虚线；工单刚变为执行中或刚完成时，对应连线短促高亮一次。工具条「关闭动效」可停用全部动画，`prefers-reduced-motion` 下自动静止——状态颜色始终保留，信息不依赖动画表达。

### 加载与缓存

打开工作台不再每次都全盘扫描：若这个会话上次看过某个任务，就直接读它并用缓存快照立即绘制，只有没有记录时才需要点「扫描任务」。

- Host 快照缓存（内存，单条上限 10 分钟、最多 8 个任务）：命中条件是「上次读过的每个文件的大小/版本」与「它们所在目录的版本」都没变，因此改写工单、新增或删除文件都会失效；同任务的并发请求合并为一次读取。命中时返回原来的 `readAt` 并附 `cached`、`servedAt`，不伪造新鲜度。
- 执行入口永远绕过缓存：确认执行前服务端会重新读一次真实工单，读到不稳定状态就拒绝。
- Client 快照缓存（`localStorage`，最多 4 个任务、单条 512 KiB）用于刷新后立刻出画面：先显示上次读到的内容并标「缓存」，同时后台校验；校验完成前「继续执行」禁用，规划不受影响。
- `discover`（找任务）另有 60 秒缓存，只有「重扫」强制绕过；它只影响任务选择器，不决定工单是否最新。

本机实测（40 工单 / 263 个 Markdown 文件）：一次 `dashboard` 冷读约 499 ms，热读仍要 289–332 ms（Python 每次都全量枚举），而缓存命中走 104 个 `stat` 只需约 8 ms。

## 并行执行

工单模型支持并行：`task_store.candidates()` 的就绪条件是「`todo`、没有领取人、所有前置已完成」，所以同一时刻可以有多项就绪；`execution_tool.py claim` 在任务锁内按入口顺序发放，不同执行者（不同 `--owner`）依次领取就会拿到不同工单，从而并行推进。

边界同样明确：工具写入仍靠 `.execution.lock` 串行，`claim` 只发第一个就绪项、不能越过未完成前置；技能文档的原文是「锁只防工具操作冲突，不替代源码并行修改协调」。工作台只读展示这件事——顶部「可并行」胶囊与图区提示给出当前就绪数量，可领取卡片带并行标记，右上详情列出「同批可并行」；看板不派发、不批量领取、不改 owner。真正并行时由使用者分别以不同 owner 领取。


扫描限额：深度 6、目录 1500、目录条目 15000、任务入口 100；跳过隐藏、依赖及生成目录。触限显示 partial，需指定更具体的扫描子目录；不是全盘无限搜索。错误入口单独显示，不当作已完成隐藏。文档预览限 256 KiB，快照输出限 1 MiB。

## 技能分工

- `game-system-development-documentation`：API 改为 `<类型>.cs.api.md` / `.ts.api.md` / `.py.api.md`。API 仅公开用途、原语言签名、必要参数返回和关键约束，链接到职责文档的操作、协作、生命周期与失败处理详情。正式与 planned/mixed 设计态仍分开。
- `game-system-development-planning`：维护类工单与 README 顺序；新增只读 `planning_tool.py dashboard --root <任务目录>`。结构化状态以类工单为准，入口不复制状态。
- `game-system-development-execution`：复用相邻规划技能的任务存储；领取、锁、owner、依赖和完成证据门禁保持不变。

文档技能提供 `migrate_api_documents.py <授权项目文档根>`，默认 dry-run；先阅读其 `--help` 和迁移预览，显式 `--apply` 才写入。仅文档 API 声明受支持，不改生产源码/SDK。目标冲突、职责归属歧义或包含实现会拒绝；新文档验证、修复授权范围引用后才删旧文件。迁移保真保留长注释到职责章节，需人工润色，进程内事务回滚不等于断电恢复。不会自动迁移其他项目。

## 构建与回归

先 `npm ci --ignore-scripts` 安装锁定的运行/测试依赖；`node scripts/build.mjs` 生成安装产物；`node --test tests/*.test.mjs` 测试 Host 操作、证据解析、依赖图布局与几何不变量、画布视口数学（适应/锚点缩放/平移/居中/方向键寻邻）、渲染结构（布局分区、aria、roving tabindex、大图降级）、缩略图池、座位判定与 Client 注册（当前 58 项）。Python 技能回归位于 `tests/workorders` 与 `tests/api-documents`，分别使用 `python -B -m unittest discover -s <目录> -v`，需要 PyYAML（本次 6.0.3）。

在本仓库中回归时，先将 `WORKORDER_SKILLS_ROOT` 环境变量设为仓库根目录（含三套相邻技能），再进入本插件目录执行以上命令。这样验证的是仓库内技能，而不是个人已安装副本。源码、测试与 lock 文件纳入 Git，`node_modules`、`dist`、`*.tgz`、缓存和临时运行样例均忽略。

零第三方构建依赖、无安装脚本。运行需要当前 DSH 的 commands/tools/fs/subprocess/skills/workingDirectory/sessionController 服务及会话 slot；Python 3 在运行环境可用，可用插件配置 `python` 指定可执行路径。技能通过 DSH skills 服务动态解析，不写死用户目录。

## 安装、兼容与恢复

先 `npm ci --ignore-scripts`、`node scripts/build.mjs` 和 `npm pack --ignore-scripts`，再使用官方 `plugin_manager install_bundle` 安装生成的 `.tgz`；不安装源码目录的 link（本次观察到 link 切归档时源目录被清空，已恢复并独立备份）。运行依赖固定为与宿主匹配的协议包 0.2.1-rc.4 与 Cordis 4.0.5，源码直接运行也需安装这些依赖。不要手改 profile 文件，不要直接复制到 DSH 核心。安装前备份插件状态和三个技能，安装只新增本包，其他插件启用状态不变。以安装返回的 live/restart-required 为准；需要重启时先保存会话，重启现有 DSH 再刷新原 GUI，不另起替代服务器。

初始目标环境为桌面 2.0.21-next、DSH 0.2.1-rc.4。Client 使用宿主 React 与原生 slot/Remote，没有私有组件导入。卸载/禁用本包应清理 slot、监听器和定时器；不删除项目工单或技能文档。技能备份可单独恢复，不能覆盖还原其他插件的后续设置。

安装成功、Host 激活、Client slot 挂载、实际视觉及忙碌交互是不同验收层级，必须分别报告。不能仅以编译、日志或 slot 存在代替实际用户交互验收。
